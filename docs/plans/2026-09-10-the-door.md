# The Door Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace brolly-server's marketing landing page with a chromeless two-panel "door" that says only what an operator configured, so one image serves many deployments without any of them claiming to be Brolly.

**Architecture:** `auth.html` — already a generic form template shared by login and register — becomes the door, and serves `/`, `/login` and `/register`. `base.html` gains `{% block header %}` / `{% block footer %}` so the door can suppress its chrome while keeping `<main>` and the skip link. A new `Chrome` struct carries instance identity and the three fine-print links onto every page struct, because the footer needs them and Askama's `{% include %}` type-checks against the including struct.

**Tech Stack:** Rust, axum 0.8.9, Askama 0.14, sqlx/Postgres, testcontainers via `brolly_test_support`.

**Spec:** [`docs/specs/2026-09-10-the-door.md`](../specs/2026-09-10-the-door.md)

---

## ⚠️ Blocker before Task 1

`BROLLY_SOURCE_URL` needs a real default. It is the AGPL §13 discharge — an
operator running a modified copy owes their users the source — and this
repository has **no configured git remote**, so it cannot be inferred.

Task 1 writes the constant as `SOURCE_URL_DEFAULT`. **Ask the user for the
canonical repository URL before writing it.** Do not invent one and do not ship
`https://github.com/`, which is what this work exists to replace.

---

## Ordering

Every task leaves the tree compiling and `main` deployable, per the trunk-based
rule. Two constraints are load-bearing:

- **Task 5 (signed-in bounce) precedes Task 8 (route `/`).** Reversed, there is
  a window where a signed-in visitor to `/` gets a login form instead of the
  personalised landing page they get today — a visible regression.
- **Task 8 (delete `landing.html`) precedes Task 9 (delete dead CSS).** The CSS
  is dead only once its last consumer is gone.

Task 2 is split out from Task 3 deliberately: the `Chrome` refactor is large and
mechanical, and it is worth landing green with **no behaviour change at all**
before anything starts depending on it.

```rust
/// The upstream repository, and the default value of `BROLLY_SOURCE_URL`.
///
/// AGPL-3.0 §13 (ADR 0003) obliges an operator running a modified copy to offer
/// their users the source. This is that offer, so it has no unset state — an
/// operator running a fork points the variable at theirs.
pub const SOURCE_URL_DEFAULT: &str = "<ASK THE USER — see the plan's blocker>";

/// What every page's chrome renders, regardless of which page it is.
///
/// One field on every page struct rather than five, because `base.html`'s
/// footer renders the fine print and Askama type-checks an `{% include %}`
/// against the *including* struct. The upside of the indirection is that a new
/// page cannot compile without it.
pub struct Chrome<'a> {
    pub instance_name: &'a str,
    pub instance_description: &'a str,
    pub source_url: &'a str,
    pub terms_url: Option<&'a str>,
    pub privacy_url: Option<&'a str>,
}

impl AppState {
    pub fn chrome(&self) -> Chrome<'_> {
        Chrome {
            instance_name: &self.instance_name,
            instance_description: &self.instance_description,
            source_url: &self.source_url,
            terms_url: self.terms_url.as_deref(),
            privacy_url: self.privacy_url.as_deref(),
        }
    }
}
```

```rust
async fn get(router: &axum::Router, path: &str) -> (StatusCode, String) {
    let (status, body, _) = get_as(router, path, None).await;
    (status, body)
}

/// Returns status, body and `Location`, because the door's whole behaviour for
/// a signed-in visitor is a redirect.
async fn get_as(
    router: &axum::Router,
    path: &str,
    cookie: Option<&str>,
) -> (StatusCode, String, Option<String>) {
    let mut request = Request::builder().uri(path);
    if let Some(cookie) = cookie {
        request = request.header(header::COOKIE, cookie);
    }
    let response = router
        .clone()
        .oneshot(request.body(Body::empty()).unwrap())
        .await
        .unwrap();
    let status = response.status();
    let location = response
        .headers()
        .get(header::LOCATION)
        .and_then(|v| v.to_str().ok())
        .map(str::to_string);
    let body = String::from_utf8_lossy(&response.into_body().collect().await.unwrap().to_bytes())
        .to_string();
    (status, body, location)
}
```

```rust
/// The unauthenticated surface names no product and no protocol.
///
/// A guard rather than a test of behaviour. The protocol cards are a plausible,
/// well-meant addition — "a member might want to know whether their Mastodon
/// client works here" — and they are how the front page becomes a pitch again a
/// year from now.
///
/// Scoped to the three templates every visitor sees. The authenticated surface
/// keeps saying "point a Solid app here", which is instruction and belongs.
///
/// Case-sensitive on purpose: `base.html` links `/static/brolly.css` and
/// `/static/favicon/…`, and those filenames must keep their names.
#[test]
fn the_unauthenticated_surface_sells_nothing() {
    const BANNED: [&str; 4] = ["Brolly", "Solid", "ATProto", "ActivityPub"];
    let templates = workspace_root().join("server/templates");

    for name in ["auth.html", "base.html", "_fine_print.html"] {
        let text = std::fs::read_to_string(templates.join(name)).expect("read template");
        for word in BANNED {
            assert!(
                !text.contains(word),
                "{name} contains {word:?}. The door says only what an operator \
                 configured; see docs/specs/2026-09-10-the-door.md."
            );
        }
    }
}
```
